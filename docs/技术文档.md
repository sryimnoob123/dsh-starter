# dsh-starter 技术文档

> 本文件是 dsh-starter 的**详细技术文档**，面向开发者和需要理解内部机制的人。
> 面向使用者的简介见根目录 `README.md`。版本基线：**v0.4.4（内置 DSH 0.1.1-rc.2）**。

---

## 1. 项目定位

`dsh-starter` 是 DeepSeek Harness（DSH）的桌面客户端——一个**极薄**的 Electron 壳：

- **不重写 DSH**：自己拉起本机的 `dsh` 服务，把官方 Web 界面装进无边框原生窗口。
- 壳只负责四件事：**窗口、托盘、通知、服务生命周期**；其余（界面、功能、agent 能力）全在 DSH 侧。
- **managed 模式**（唯一模式）：壳**拥有并启动自己的 DSH 服务**，不复用外部已装的服务。

---

## 2. 架构总览

```
┌─────────────────────────────────────────────────────────┐
│  Electron 主进程（src/main）                              │
│  ├─ app.ts           启动序列 + 服务生命周期 + 窗口/托盘    │
│  ├─ service/         spawn、端口探测、rpc、watchdog        │
│  ├─ install/         dsh 安装 + 捆绑插件 + win32 修复插件   │
│  ├─ onboarding/      首启向导（API 接入）                  │
│  ├─ window/          无边框外观、拖拽条、设置扩展注入        │
│  ├─ runtime/         Node 运行时自动补齐                   │
│  ├─ updater/         electron-updater 自动更新             │
│  ├─ bridge/          渲染进程 ↔ 主进程 IPC 桥（dshShell）  │
│  └─ config/logging/notify/usage/watchdog 等基础设施        │
└──────────────┬──────────────────────────────────────────┘
               │ DSH_HOME=<安装目录>/dsh-home
               ▼
┌─────────────────────────────────────────────────────────┐
│  DSH 服务（<安装目录>/dsh/node_modules/@deepseek-ai/dsh）  │
│  · 打包时打进安装包（离线），壳用 node 直跑 lib/bin.js      │
│  · 官方 Web GUI 渲染进壳窗口（http://127.0.0.1:<port>）    │
│  · 配置/凭据/会话/插件全在 dsh-home 里                     │
└─────────────────────────────────────────────────────────┘
```

**核心原则**：壳极薄、可扩展（[FR-6]）；服务端能力优先做成 DSH 侧插件，壳只做承载面。

## 4. 关键机制详解

### 4.1 服务生命周期（managed 模式）

1. 启动序列（`app.whenReady` → `startShell`）：
   检测 dsh → 探测端口 → `spawn` → 等服务就绪（stdout URL 行 或 端口探测）→ 加载页面。
2. **dsh 来源**：优先内置 `<安装目录>/dsh`（打包时打入），其次 PATH 全局 dsh（此时弹窗问用哪个）。
3. **DSH_HOME**：经环境变量注入，指向 `<安装目录>/dsh-home`（壳 exe + dsh + 数据三样同目录）。
4. **崩溃自愈**：服务曾就绪后崩溃 → 指数退避重启（≤5 次）；主动停止/退出则置 `intentionalKill` 不再自愈。
5. **端口**：智能探测（默认 3080，冲突自动换空闲端口，记住用过的端口）。

### 4.2 打包 / 安装（离线，v0.4.4 链路）

**打包链路**（`pnpm dist` 串联）：
1. `scripts/prepare-dsh.mjs`：打包前用 **pnpm 隔离目录安装** `@deepseek-ai/dsh`（`nodeLinker: hoisted`）再移入 `vendor/dsh`。
   （npm 走代理会卡死、pnpm 在 workspace 内会跳过 vendor——所以隔离目录 + 移入；npmmirror 直连不通，需走本地代理。）
2. `scripts/prepare-seed.mjs`：从快照 `_tmp/backups/snapshots/seed-20260823-preload/` 净化出种子 `build/dsh-home-seed/`——
   只保留 `profiles/web/`（package.json、cordis.patch.yml、cordis.yml、pnpm-workspace.yaml、pnpm-lock.yaml、node_modules 106 插件实体）
   + **settings.yaml**（非敏感配置：皮肤/主题/权限/模型引用名，无凭据）。剔除一切隐私（.credentials.yaml/sessions/storages/undo-snapshots/.cache/日志/*.bak）。
   另外把 patch 显式引用的官方包 `@deepseek-ai/dsh-plugin-manager` 实体从 vendor/dsh 补进种子 web node_modules（DSH 自己管理 profiles fallback 层，patch 引用的包必须实体存在才能解析——2026-08-23 真机教训）。
3. `tsc && postbuild`：编译壳 + 桥契约护栏（31 通道同步检查）。
4. `electron-builder --win --config build/electron-builder.yml`：
   - **NSIS 默认 7z 压缩载荷**（**不要设 `compression: store` / `useZip: true`**——那是逐文件直写，5 万+ 文件安装分钟级；7z 载荷安装时解压秒级-十秒级且带进度条。2026-08-23 调研生态共识：EAC/dsh-studio/anywhere-labs 均如此）。
   - `extraFiles`：`vendor/dsh/node_modules` → `<安装目录>/dsh/node_modules`；`build/dsh-home-seed` → `<安装目录>/dsh-home-seed`。
     **注意用 extraFiles（落安装根，与 exe 同级）而非 extraResources（会落 resources/）**——壳 `shellInstallDir()` 返回 exe 目录。
   - **`asarUnpack: plugins/**/*`**：内置插件必须解包到 `app.asar.unpacked/`——Electron 的 asar 虚拟文件系统只读，`fs.cpSync` 从 `app.asar/plugins` 复制必然 ENOENT（2026-08-23 真机：pre-sync failed + 黑屏）。壳侧 `bundledPluginsSourceRoot()` 打包版优先 unpacked 路径。
   - `oneClick:false` + `allowToChangeInstallationDirectory:true`（2026-08-23 拍板：可换安装目录）。
- 安装时**零联网、零 npm**，双击即用。DSH 版本**锁定为 `^0.1.1-rc.2`**（vendor/dsh/package.json），升级需显式改版本 + 全量回归。
- pnpm 11 注意事项：新发布的包会被供应链策略（`minimumReleaseAge`）拒绝——需在 pnpm-workspace.yaml 设 `supplyChainPolicy: minimumReleaseAge: 0`；build scripts 被忽略时用 `pnpm approve-builds --all`（非交互）。

**首启播种（两阶段，2026-08-23 定序）**：
- **阶段 1**（spawn 前，`seedProfileFromBundled`）：`dsh-home/profiles/web` 缺失时从 `dsh-home-seed/profiles/web` 整体拷贝（106 插件 + patch + manifest）。必须先于 `ensureBundledDshPlugins`（否则 ensure 先建骨架 → 播种检测 profile 存在跳过）。
- **阶段 2**（service ready 后，`finalizeSeedSettings`）：DSH 已完成初始化、不会再覆盖 settings——settings.yaml 缺失或为 48B 空壳（仅 permission 默认段）时补种子的完整配置（皮肤/主题/权限/模型引用/插件配置）；用户改过（有实质内容）绝不动。随后删 `dsh-home-seed/` 残留——终态目录 = exe + `dsh/` + `dsh-home/` 三件套。
- **API key 不在种子**（在 `.credentials.yaml`，不打包）：用户装好后自行配置一次模型/密钥。
- **MAX_PATH 防护**（EAC issue #4 血泪）：NSIS 7z 解压对完整路径 >260 字符的文件**静默丢失**。打包前用 `scripts/maxpath-scan.mjs` 扫描种子与 vendor 树；当前种子无超长路径。

### 4.3 自动更新

- `electron-updater`：**自动检查 + 用户点击才下载**（`autoDownload=false`），**安装由用户确认**（`quitAndInstall`）。2026-08-23 拍板「下载应该是我点了之后才开始的」。
- 发布源 = GitHub Releases（`latest.yml` + NSIS 安装包 + blockmap）。
- **升级保护（v0.4.8 重写）**：`build/installer.nsh` 三层防线，保证用户数据（`dsh-home`：会话/技能/配置/凭据）跨版本更新不丢：
  1. **customInit 宏**（`.onInit` 阶段，早于旧 uninstaller 执行）：从注册表读旧 InstallLocation，把旧 `dsh-home` 完整复制到 `%TEMP%\dsh-home-backup`——覆盖「从旧版本（0.4.3 及更早）直接更新」场景，旧 uninstaller 删数据前已备份。
  2. **customRemoveFiles 宏**（更新时）：把 `dsh-home` 移到 `%TEMP%\dsh-home-preserve`，新安装器 customInstall 移回。
  3. **壳侧备份**（`updater/index.ts` 的 `backupDshHomeBeforeUpdate`）：用户点「现在安装」时再备份一份到 `%TEMP%\dsh-home-backup`。
  - 启动时双通道恢复（`restorePreservedDshHome.ts`）：先试 NSIS preserve，再试壳侧备份；dsh-home 为空壳才恢复（不覆盖用户新数据），恢复成功清理备份。
  - 2026-08-25 全真模拟实测：0.4.3→0.4.8 与 0.4.7→0.4.8 两轮，技能/会话/凭据/配置全部保留。
- **NSIS 必须 `oneClick: true`**：带向导的 assisted 安装器（`oneClick:false`）在 electron-updater 静默拉起时无法无人值守走完向导、会挂起，导致自动更新装不上。v0.4.1 实测踩到（已发布的 v0.4.1 正是 assisted 包）。已改 oneClick 并**实测静默安装/升级重装/本地假源更新全链路通过**（见 §7 B1）。
- **`resources/app-update.yml` 必须存在**：electron-builder 产物会自动内嵌；但手工拷贝/精简出来的测试目录常漏它 → `checkForUpdates` 读不到发布源而**静默失败、无任何提示**。排查「点更新没反应」先确认这个文件在。
- **当前更新 UX（O1 已落地 + 2026-08-23 迭代）**：
  - 提示条唯一入口（`desktopChrome.ts`）：available「发现新版本，点此下载」可点 / downloading「正在下载新版本（X%）」禁点 / downloaded「**下载已完成，请点击安装**」可点 / checking「检查更新中…」禁点 / none 隐藏。**文案通用化去版本号**（用户拍板「更新机制是全局的，不是某个版本的」）。
  - 点击才下载：`autoDownload=false` + `availableUpdateVersion`（available 记、downloaded/not-available 清）+ `startDownload()`；统一入口 `checkForUpdates` 三分支：有待装→安装 / 有 available→startDownload / 都无→checkForUpdatesManually。
  - 进度小窗（`pages/update.html` + `updater/progressWindow.ts`）：available 阶段显示「下载」按钮。
  - 安装确认框文案预告（窗口会关、安装器接管显示进度、装完自动重启）；`setImmediate(() => quitAndInstall())` 防挂起 IPC 竞态；`before-quit` 杀 DSH 服务子进程防文件锁。
  - 防重复检查（B5 已修）：悬浮「检查更新」按钮只响应真实用户点击（`isTrusted`），合成 click 一律忽略；`checkForUpdatesManually` 另加 10s 防抖。

### 4.4 窗口外观（无边框 + 原生拖拽）

- `frame:false` + 自绘标题栏（悬浮窗口按钮：检查更新/最小化/最大化/关闭，右上角）。
- **拖拽 = 原生 `-webkit-app-region: drag` 顶部 24px 拖拽条**（`DRAG_BAR_SCRIPT`）：
  - 原生拖拽由 Windows 处理 → 无 DPI 漂移、**自带双击最大化**、正确配合缩放边与 Aero 贴靠。
  - 顶部 24px 内的 DSH 交互元素由脚本动态标 `no-drag` 并抬到拖拽条之上，保持可点。
  - 顶部会话 header 标题行加 150px 右 padding，给悬浮按钮让位。
- **历史教训**：早期版本用 JS `setPosition` 16ms 循环拖拽，在 150% 缩放下 DIP/物理像素换算漂移 → 窗口"越拽越大"——已整体废弃，改用原生拖拽。

### 4.5 提示词 / 身份 / persona 注入（插件承载，随壳内置）

- **注入本体在插件**：`src/main/prompt/` 只保留纯函数；实际注入由插件 `@dsh-desktop/plugin-global-prompt` 承担（源码 `plugins/plugin-global-prompt/`，**2026-08-23 起重新随壳内置**——2026-08-22 曾独立发布不捆绑，后回滚内置）。
- **内置方式**：`BUNDLED_DSH_PLUGINS` 登记 → 服务就绪后同步（拷贝到 runtime + junction 进 profile + manifest 注册 bundle）→ 每次启动幂等确保。
- 插件功能：
  - **全局 AGENTS.md**（`$DSH_HOME/AGENTS.md`）编辑器，原子写 + 配置 watch 热同步；
  - **项目级 AGENTS.md**（工作区路径经 DSH workspaceRegistry 服务端解析，防任意路径写入）；
  - **agent-instructions 重新启用**：DSH web-app bundle 默认 `disabled: true` 关闭该机制，插件的 bundle patch 以 `- id: agent-instructions / disabled: false` 覆盖（bundle 层在 web-app 之后，last-write-wins）；
  - **身份注入**（`harness:identity` 段）与 **persona 注入**（`deployment:persona` 段）经 `system-prompt/assemble` 瀑布事件注入；`{{model}}`/`{{cwd}}` 占位符由 DSH 渲染期展开（变量注册于 dsh-agent-loop）；
  - **运行时上下文开关**（`includeRuntimeContext`）：关闭时调用 `systemPrompt.suppressRuntimeContext()`；
  - **输入校验**：persona ≤ 20k 字符、指令文本 ≤ 1MiB UTF-8，超限 HTTP 400；
  - **一键注入**：勾身份 + 人设 + 填 DSH web 基线模板；
  - **结果通知开关**：读壳配置（`notifications.result`）。
- **独立发布副本**（2026-08-22 曾发布，现保留作外部安装源）：`E:\projets\dsh-starter\plugin\提示词\plugin-global-prompt`，可用 `dsh plugin add` 单独安装（壳内置版与独立版并存互不干扰）。

### 4.6 首启向导 / API 接入

- 向导 = **通用 OpenAI 兼容表单**（`onboarding/connection.ts`）：填 baseURL + API Key + 模型名，支持「获取模型列表」（`GET /v1/models`）+ 测试连接。（早期 llm-pi-ai/llm-deepseek/Zen 渠道选择已通用化合并，2026-08-23 现状）
- 保存后经 `settings.update` 写 DSH 官方 provider 配置；新会话默认权限 = Full access（`danger-full-access`，只写一次，用户手改不覆盖）。

### 4.7 win32 持久终端修复（捆绑插件）

**问题**：DSH 官方 `@deepseek-ai/dsh-subprocess-local` 的 `createProcessInspector()` 只有 Linux/macOS 后端，Windows 上持久终端（`tool-bash-persistent`）一 spawn 就抛 `terminal inspection is unsupported on platform win32`。

**修复**：捆绑第三方插件 `dsh-win-terminal-inspector`（MIT，© 2026 clearkurt，**原样未改**）：
- vendor 位置：`vendor/win-terminal-inspector/`（含 LICENSE/NOTICE/源码），打包进 asar。
- 首启自动装：`src/main/install/winInspectorPlugin.ts` 在服务就绪后，把插件文件落到 `<DSH_HOME>/profiles/web/plugins/dsh-win-terminal-inspector/`，并在 **web profile 的** `cordis.patch.yml` 幂等追加 insert 条目。
- 装一次记一次（`shell-config.json` 的 `winTerminalInspectorInstalled`），用户手动卸载后不反复重装。
- 插件经 DSH 官方 `terminalInspector` 钩子注入，不修改任何官方 node_modules，卸载即还原。

**沙箱边界（O2-A 已落地）**：新会话默认权限改为 **Full access**（`danger-full-access`），持久终端开箱即用。实现：壳服务就绪后经 `settings.update({ns:'permission', patch:{defaultPreset:'danger-full-access'}})` 写 DSH 官方设置；按 `shell-config.json` 的 `permissionDefaultApplied` **只写一次**，之后用户手改壳不覆盖。代价：Full access 下命令不受文件沙箱约束。

### 4.8 捆绑 DSH 插件（bundle 机制）与颜色自定义（背景已暂停）

- **bundle 注册**：壳内置插件经 profile manifest 的 `dsh.profile.bundles` 数组注册（DSH 0.1.0-rc.8+ 机制；rc.6 的 `- insert` 进 cordis.patch.yml 会被判 duplicate loader entry，已弃用）。
  捆绑列表 = `src/main/install/bundledDshPlugins.ts` 的 `BUNDLED_DSH_PLUGINS`（**2026-08-23 现状 5 项**）：
  `@dsh-desktop/plugin-global-prompt`（提示词）、`dshmarket`（插件市场）、`dsh-boot-guard`、`dsh-undo-savepoint`、`@moonquake2004/dsh-doctor`（后三者零 npm 依赖，整合包自救层）。
- **同步流程**（服务就绪后执行）：源 `plugins/<dir>` → 复制到 DSH runtime 的 `node_modules/@dsh-desktop/*` →
  junction 进 `profiles/web/node_modules/@dsh-desktop/*` → manifest 追加 bundle 名（幂等）。
  插件 import 的 `@deepseek-ai/*` peer（schemastery/dsh-settings/dsh-home-paths 等）从 .pnpm store 链接到顶层。
- **退役清理**：不再捆绑的 `@dsh-desktop/*` 从 manifest 移除、junction 用 `unlinkSync` 删除（Windows 上
  `rmSync(force)` 对 junction 抛 "Path is a directory"，`rmSync(recursive)` 会跟随 junction 删掉 runtime 真目录——都不能用）、

### 4.10 插件自救机制（shell-rescue 独立库 + 壳接线）

> 独立库 `E:\projets\自救`（git main），产物经 `npm run sync -- <壳路径>` 同步进 `src/main/vendor-rescue/`（只读）。**改动一律先在独立库做**（独立开发 → 接入宿主 → 宿主反馈 → 回独立改的闭环）。

**架构**：崩溃 → `createRescueEngine`（独立库核心）喂 `CrashReport` → `runDiagnosers` 诊断 → `planRescue` 决策（repair / isolate / give-up）→ 处置 → 递归重启。

**诊断规则**（`src/main/vendor-rescue/dsh/rules.ts`，注册顺序敏感）：
1. `dsh-module-not-found`：`Cannot find package|module 'X'` → 归因插件 → 隔离。
2. `dsh-duplicate-entry`：`duplicate loader entry id: X` → repair `drop-duplicate-insert`（清 patch insert 块）。
3. `dsh-bad-patch-yaml`：YAML 解析失败（跨行限长正则）→ repair `restore-patch-yaml`（从 .bak 恢复 + 净化）。**必须排在 loader 规则前**（否则 YAML 崩被 loader 规则吞掉）。
4. `dsh-fallback-blocker`：`profiles/node_modules` 被真实目录挡住（锚定前缀，防 runtime 层误触发）→ repair `purge-fallback-blockers`（v0.4.4：DSH 对依赖闭包 BFS 校验、一次只报第一个实体 → 单包修复烧完预算；改为一次清空全部非 symlink 实体，DSH 重建整个闭包）。
5. `dsh-loader-entry-failed`：`failed to apply|import loader entry <id> (<pkg>)` → 归因插件 → 隔离。

**隔离 = 移走不是删除**（2026-08-23 拍板）：实体 rename 到 `userData/rescue-backups/<pkg>/`（meta.json 记录还原所需全部状态：manifest/patch 原文 + runtime/profile 实体），弹窗「恢复插件」一键装回。三道闸：包名白名单 + `@deepseek-ai/` 官方保护 + isInside 路径包含校验。

**repair 通道**（非破坏性，不烧隔离预算）：
- `drop-duplicate-insert`：patch 层清重复 insert 块（`join('
')` 补回换行防粘连坏 YAML）。
- `restore-patch-yaml`：读 `cordis.patch.yml.bak` → `sanitizePatchForRestore` 净化（剔除已隔离插件块，防 module-not-found 连环崩）→ 写回。
- `purge-fallback-blockers`（v0.4.4 新增）：遍历 `profiles/node_modules` 顶层，全部非 symlink 实体目录移入 backupRoot（symlink 保留，移走不删除，可恢复）；只移目录不动文件，路径 isInside 校验；幂等（无实体即 clean）。

**循环防护**（2026-08-23 对抗审查 C3/C4 修复）：
- 引擎 `maxRepairsPerWindow=3`（修复成功但依旧崩时防无限 repair→restart 循环，超限 give-up）。
- 壳坏 YAML 回退 `badYamlRestoreAttempts ≤ 3`（.bak 也坏时防 `startShellInner` 无限递归）。

**诊断报告**（`generateDiagnosticReport`）：三段式 markdown（问题[脱敏] / 状态 / 指令），自动复制剪贴板 + 落盘 `userData/diagnostic-reports/` 环形 20 份；`readDiagnosticLogTail` 日志瘦身（截尾 64KB → 剥 ANSI → 最近一次根因窗口 → 限 30 行）。

**渲染进程崩溃**（缺口 1，`window/renderGone.ts`）：`render-process-gone` 监听 → 2 分钟窗口 3 次上限自动 reload → 停手提示；`STATUS_BREAKPOINT`（exitCode -2147483645 = 0x80000003，杀软/调试器打断特征）→ security-guard 提示不自动 reload，不计入崩溃预算、通知节流。

**热挂载失败**（缺口 2，`service/hotMount.ts`）：stderr 扫描三形态——`hot mount of X failed` / `client-modules: bundle ... loaded without registering "id"` / 嵌套 loader entry（取最内层权威包名）；包名过白名单 + 剥版本尾 + 拒文件名形态 → 自动隔离 → 重启 → 提醒。同一包只处理一次（Set 防刷屏）。
